# meguri

買い物の調査で、毎回同じになる作業を受け持つ CLI。販路（97サイト）の検索URLを組み立て、HTTP で取れるサイトは取りに行き、価格・送料・在庫などを抜き出して、税込・送料込みの支払額でそろえる。どのサイトを当たって何が出たか（どこまで探したか）も一緒に出す。

買わない。ログインしない。カートにも入れない。同じ品かどうか、状態はどうか、どれを選ぶかは、人（かエージェント）が決める。

## すぐ試す

Nix（flakes が有効なもの）が要る。このフォルダで：

```bash
nix build
```

```bash
./result/bin/meguri search "WH-1000XM5" --min-price 12000
```

初回のビルドは数分かかる。検索は40秒ほどで、候補の一覧と「どこまで探したか」が出る。

毎回 `./result/bin/meguri` と打つ代わりに、このシェルの間だけ `meguri` で呼べるようにするなら：

```bash
alias meguri="$PWD/result/bin/meguri"
```

`nix run . -- search "WH-1000XM5"` でも同じように動く（ビルドも兼ねる）。以下では `meguri` と書く。

## ひととおりの流れ

### 1. 探す

```bash
meguri search "WH-1000XM5" --min-price 12000
```

```text
候補（未確認）322件のうち、安い順に40件　※一覧の値。個別ページで確かめるまで確定ではない
サイト	支払額	送料	在庫	商品名	URL
hardoff	¥12,100+送料	送料は配送先しだい	販売中	SONY BTヘッドホン WH-1000XM4	https://netmall.hardoff.co.jp/product/6531583/
hardoff	¥13,200+送料	送料は配送先しだい	販売中	SONY ヘッドホン WH-1000XM4	https://netmall.hardoff.co.jp/product/6128179/
…

どこまで探したか：取得17・0件12・ブラウザで開く58・ブロック2・停止中5・対象外7（サイト×検索語×種類の行数）
kakaku	新 取得101件・最安¥31,799
rakuten	新 取得45件・最安¥1,470 ／ 中古 取得45件・最安¥5,480
yodobashi	新 ブラウザで開く：画面ありの通常のブラウザが要る	https://www.yodobashi.com/?word=WH-1000XM5&…
hands	新 0件
…

実行 20261121-114422：~/.cache/meguri/runs/20261121-114422（candidates.jsonl・coverage.jsonl を jq で読む。…）
```

- **候補は未確認。** 検索結果の一覧から読んだ値で、個別ページを見るまで確定ではない。
- **支払額**は、税込価格＋送料。`¥12,100+送料` は、送料がまだ分からない（少なくともこの額）という意味。`送料?`・`在庫?` は、一覧に表示が無い。
- **`--min-price`** は、付属品よけ。型番で探すと、安い順の上にイヤーパッドやケースが並ぶ。本体の相場より下の額を入れると、標準出力から外れる（実行のファイルには全部残る）。`--max-price` もある。
- **検索語は複数書ける。** `meguri search "WH-1000XM5" "4548736132566"` のように型番・JAN・商品名を並べると、結果をまとめる。価格.com は、JAN で探すと製品ページが出ない（0件になる）ので、型番か商品名も入れる。
- **サイトの検索は緩いことがある。** 上の例では、ハードオフが WH-1000XM5 の検索に XM4 を返している。同じ品かどうかは、商品名を見て決める。
- 新品だけ・中古だけなら `--kind new`・`--kind used`。サイトを絞るなら `--only rakuten,hardoff`、区分で絞るなら `--category リユース`。

「どこまで探したか」の読み方：

| 表示 | 意味 |
|---|---|
| 取得◯件・最安¥… | 検索結果を読めた |
| 0件 | サイトが「該当なし」と返した |
| ブラウザで開く | HTTP では読めない（か、まだ読み方を作っていない）。行の右のURLを、ブラウザで開いて見る |
| ブロック | 403 やボット確認が出た。そのサイトは、そこでやめている |
| 停止中 | サイトがメンテナンスや休止中 |
| 対象外 | 買う販路ではない（通販が無い、など） |
| 失敗 | つながらない、ページの作りが変わった、など |

### 2. 上位の個別ページを確かめる

```bash
meguri verify --top 10 --min-price 12000
```

```text
読み直した5件：確認済み5
判定	支払額	変化	商品名	URL
確認済み	¥12,100+送料	変化なし	SONY BTヘッドホン WH-1000XM4	https://netmall.hardoff.co.jp/product/6531583/
…
```

候補の安い順に、個別ページを取りに行って読む。一覧のときと価格や在庫が変わっていれば「変化」に出る。もう一度走らせると、前に読んだページを読み直す。

判定は3つ。

| 判定 | 意味 |
|---|---|
| 確認済み | 個別ページで、名前・税込価格・送料・在庫・販売者・画像・購入の入口の7項目をすべて読めた |
| 一部 | 個別ページを読んだが、足りない項目がある |
| 未確認 | 一覧の値だけ |

### 3. ブラウザでしか開けないサイトを足す

「ブラウザで開く」の行のURLを、ふつうのブラウザで開いて探す。気になる商品のページを保存すれば、meguri に読ませられる。

ページを開いて、開発者ツールのコンソールで次を実行すると、いま表示されているHTMLがクリップボードに入る。

```js
copy(document.documentElement.outerHTML)
```

macOS なら、それをファイルに落として渡す。

```bash
pbpaste > saved.html
```

```bash
meguri item "https://www.yodobashi.com/product/100000001007090035/" --html saved.html
```

- 保存したHTMLを読めるのは、ヨドバシ、ヤマダ、ケーズデンキ、ニトリ、Amazon、メルカリ、2nd STREET、じゃんぱら、eBay。ほかのサイトのページは、読める項目だけ読んで「一部」にとどめる。
- URL は、そのページのURLを渡す（どのサイトの読み方を使うかを、URLで決める）。
- ログインした状態で保存すると、名前や住所がHTMLに入ることがある。保存したファイルを実行のフォルダの `pages/` に置けば、実行と一緒に7日で消える。

### 4. 重複を除いて並べる

```bash
meguri rank --min-price 12000
```

同じURLと、同じ在庫（2nd STREET の自社EC・楽天店・Yahoo!店など）を1つにまとめ、枠ごとに安い順に並べる。枠は、すぐ買える（新品・即決）／入札次第（オークション）／訳あり（ジャンク・アウトレット）／中古／いまは買えない。個別ページを読んだものが、一覧だけのものより先に来る。

### 5. 表にする

```bash
meguri render --format md --min-price 12000 > result.md
```

「候補」（確認済みのもの。画像・支払額・在庫・購入のリンクつき）、「未確認の候補」、「どこまで探したか」の3つの表が、Markdown で出る。

## そのほかのコマンド

```bash
meguri item "https://netmall.hardoff.co.jp/product/6531583/"
```

個別ページを1つ読み、項目ごとに「どこから読んだか」をつけて出す。読めなかった項目は `null` で、理由が横に出る。

```text
判定	confirmed（確認済み）
サイト	hardoff	取得 11/21 11:47
URL	https://netmall.hardoff.co.jp/product/6531583/
名前	SONY BTヘッドホン WH-1000XM4	個別ページ/JSON-LD
税込価格	¥12,100	個別ページ/本文
税抜価格	¥11,000	個別ページ/JSON-LD	JSON-LD の価格は税抜
送料	送料は配送先しだい	個別ページ/本文	都道府県ごと。…
支払額	null（価格か送料が分からない）
在庫	在庫あり	個別ページ/JSON-LD
販売者	ハードオフ横浜長津田店	個別ページ/本文
…
```

```bash
MEGURI_PREF=13 meguri ship "https://netmall.hardoff.co.jp/product/6531583/"
```

配送先までの送料を、サイトの送料計算に問い合わせて入れる（上の例なら、送料¥600・支払額¥12,700）。いま使えるのは、ハードオフとトレジャーファクトリー。`MEGURI_PREF` は、都道府県コード（01〜47）か都道府県名。設定してあれば、`item` と `verify` でも同じように問い合わせる。配送先は、キャッシュにも実行のフォルダにも残さない。

```bash
meguri sold "WH-1000XM5" --min-price 12000
```

ヤフオクの落札相場。件数・最安・中央値・最高と、落札された出品が出る。

```bash
meguri recall "ヘッドホン" "headphone"
```

消費者庁と米国 CPSC のリコール情報。CPSC は英語で探すので、英語の語も並べる。題に語が入っているだけのものも混ざるので、対象の型番と期間はリンク先で確かめる。

```bash
meguri sites
```

販路の一覧（id・名前・区分・どの方法で読めるか）。`--only` に渡す id は、ここで分かる。サイトごとの注記は [docs/channels.md](docs/channels.md) にある。

```bash
meguri check --only hardoff,rakuten
```

サイトごとの健康診断。検索を1回、個別ページを1件当てて、いまも読めるかを見る。サイトの作りが変わって読めなくなったら、ここで分かる。

## 共通のオプション

| オプション | 意味 |
|---|---|
| `--format table\|jsonl\|md` | 出力の形。既定は `table`（タブ区切り） |
| `--fresh` | キャッシュを使わず、取り直す |
| `--run <id>` | どの実行を使うか。既定は直前の実行 |

どのコマンドも `--help` で、そのコマンドのオプションが出る。

終了コードは、0＝成功（一部のサイトがブロックでも成功）、2＝使い方の誤り、3＝取りに行った全サイトで失敗（`item` なら、そのページを取れなかった）。

## 実行のファイル

`search` を走らせるたびに、実行のフォルダが1つできる（`~/.cache/meguri/runs/<id>/`。`$XDG_CACHE_HOME` があれば、その下）。`verify`・`item`・`rank`・`sold`・`recall` は直前の実行に書き足し、`render` はそこから表を作る。7日たつと消える。

| ファイル | 中身 |
|---|---|
| `candidates.jsonl` | 検索で見つけた候補の全部（標準出力に出なかったものも） |
| `coverage.jsonl` | どこまで探したか |
| `items.jsonl` | 個別ページを読んだ記録 |
| `sold.jsonl`・`recalls.jsonl`・`ranked.jsonl` | `sold`・`recall`・`rank` の結果 |
| `pages/` | 取ったページ。ブラウザで保存したHTMLも、ここに置くと一緒に消える |

標準出力は短く切ってある（30KB以内）。細かい中身は jq で読む。フォルダの場所は、`search` の出力の最後の行に出る。

```bash
jq -r 'select(.offer.site=="hardoff") | [.offer.priceIncl.value, .offer.name.value, .offer.url] | @tsv' ~/.cache/meguri/runs/<id>/candidates.jsonl
```

```bash
jq -r 'select(.status.tag=="NeedsBrowser") | [.site, .url] | @tsv' ~/.cache/meguri/runs/<id>/coverage.jsonl
```

## 値の決まり

- **数字は作らない。** 読めなかった値は `null` にして、理由を書く。税抜しか書いていなければ、税込は `null`（計算しない）。送料が配送先しだいなら、支払額は `null`。
- **値ごとに出どころを持つ。** 一覧から読んだのか、個別ページのどこ（JSON-LD・本文など）から読んだのかが、`item` の出力と JSON Lines に入る。
- **確認済みは、個別ページを読んだものだけ。** 一覧の値から「確認済み」は作らない。
- **ポイントは参考。** ログインしていない状態の表示なので、実際とは違うことがある。

## サイトへの当たり方

- `meguri/<版> (+リポジトリのURL)` と名乗る。ブラウザのふりはしない。
- 同じホストへは同時に1本、間隔は2秒以上。全体でも同時に8本まで。
- 取ったページは15分キャッシュする。同じ検索を続けて走らせても、サイトには当たらない。
- 403・429・ボット確認が出たら、そのサイトはそこでやめて「ブロック」と記録する。解いたり避けたりしない。
- 検索結果は1ページ目だけを読む。
