# meguri

探している物について、買える候補を各サイトから集め、購入ページまで開いて確かめた結果を返す CLI。価格・送料・支払額・在庫・状態・販売者・購入の入口と、そのページを確かめた時刻が、1件ずつ構造化されて返る。どのサイトを当たって何が出たか（どこまで探したか）も一緒に出す。

買わず、ログインせず、カートにも入れない。同じ品かどうか、どれを選ぶかは、人（かエージェント）が決める。その判断は条件として書くか、判定モデル jev や外のコマンドに任せるかして、何個でも渡せる。

## すぐ試す

Apple Silicon の Mac か Linux に Nix（flakes が有効なもの）があれば、入れずに1行で走らせられる。

```bash
nix run github:yuidvg/meguri -- search "WH-1000XM5" --min-price 12000 --has XM5
```

- 初回は依存を取ってきて meguri をビルドするので、結果が出るまでに時間がかかる。
- 検索そのものは1分ほどで返る。
- flakes を有効にしていない Nix なら、`nix` のすぐ後ろに `--extra-experimental-features 'nix-command flakes'` を足す。Nix が無ければ、[nixos.org の手順](https://nixos.org/download/)で入れる。
- Intel の Mac 向けのビルドは無い。Linux は aarch64 でビルドとテストが通ることを確かめた。x86_64 では確かめていない。

## 入れる

### nix-darwin を使っている場合

システムの flake に、入力を1つと、パッケージを1つ足す。

```nix
{
  inputs = {
    # …いまの入力…
    meguri.url = "github:yuidvg/meguri";
  };

  outputs = inputs@{ nix-darwin, ... }: {
    darwinConfigurations."<ホスト名>" = nix-darwin.lib.darwinSystem {
      modules = [
        # …いまのモジュール…
        ({ pkgs, ... }: {
          environment.systemPackages = [ inputs.meguri.packages.${pkgs.stdenv.hostPlatform.system}.default ];
        })
      ];
    };
  };
}
```

```bash
sudo darwin-rebuild switch --flake .#<ホスト名>
```

- `meguri.inputs.nixpkgs.follows` は付けない。meguri は自分の flake.lock の nixpkgs でビルドとテストを確かめている。
- home-manager で入れるなら、同じものを `home.packages` に入れる。
- 新しいバージョンにするときは、`nix flake update meguri` のあと、もう一度切り替える。

### それ以外

```bash
nix profile add github:yuidvg/meguri
```

- 新しいバージョンにするときは `nix profile upgrade meguri`、消すときは `nix profile remove meguri`。
- `nix profile add` が無い古い Nix では、`nix profile install` と書く。

## search：何を → どこを → 結果

`search` の形は「何を探すか → どこを探すか → 結果」。1回の呼び出しで、個別ページ（購入ページ）を読むところまで済ませて返す。結果は渡した入力だけで決まる。前に走らせた結果を読んで続きに使うことはない。

| 入力 | 中身 | オプション |
|---|---|---|
| 何を | 検索語と、見つけた売り物のうち「探している物」と認める選び方 | `語...`・`--min-price`・`--max-price`・`--has`・`--not`・`--judge`・`--judge-cmd` |
| どこを | 当たる販路の選び方、新品・中古、名指しのページ | `--only`・`--skip`・`--category`・`--judge-channel`・`--judge-channel-cmd`・`--market`・`--url`・`--page` |
| どこまで | 個別ページを読む数と、かける時間 | `--read`・`--time` |

選び方は**条件**と**判定**でできている。条件は1件ごとに決まる（価格・商品名・販路の id など）。判定は判断を外に任せる（判定モデル jev か、外のコマンド）。どちらも何個でも書けて、選ばれるのは「全部を満たすもの」。書く順は結果に関係しない（条件を先に、判定を後にかける）。

`search` は次の順に動く。

1. 「どこを」の選び方で、カタログから当たる販路を選ぶ。選び方が無ければ、全部の販路に当たる。
2. その販路の検索結果の一覧を並列に取る。
3. 「何を」の選び方で、一覧で見かけた売り物のうち、探している物を選ぶ。
4. 選んだものの個別ページを、販路と新品・中古の組ごとに安い順で3件ずつ読む。判定が無ければ、一覧が取れた販路から順に読み始める。
5. 個別ページの値で、条件をもう一度かける。同じ在庫をまとめ、枠（すぐ買える／入札次第／訳あり／中古／いまは買えない）に分ける。

### 読み方

| 列 | 意味 |
|---|---|
| 判定 | `確認済み`＝個別ページで、名前・税込価格・送料・在庫・販売者・画像・購入の入口の7項目をすべて読めた。`一部（◯◯なし）`＝読んだが、足りない項目がある |
| 支払額 | 税込価格＋送料。`¥16,500+送料` は、送料の額が決まらない（配送先しだい、など）ので、少なくともこの額 |
| 確認 | その個別ページを読んだ時刻 |
| 注記 | 読めなかった項目の理由、値についての但し書き、一覧の値からの変化（`価格 ¥20,500→¥20,000`）、同じ在庫がほかのサイトにもあること |

「どこまで探したか」の読み方は次のとおり。

| 表示 | 意味 |
|---|---|
| 取得◯件・最安¥… | 検索結果を読めた |
| 0件 | サイトが「該当なし」と返した |
| ブラウザで開く | HTTP では読めない（か、まだ読み方を作っていない）。行の右のURLをブラウザで開いて見る |
| ブロック | 403 やボット確認が出た。そのサイトはそこでやめている |
| 停止中 | サイトがメンテナンスや休止中 |
| 対象外 | 買う販路ではない（通販が無い、など） |
| 失敗 | つながらない、時間切れ、ページの作りが変わった、など |

## 何を：探している物の選び方

一覧で見かけた売り物のうち、どれを「探している物」と認めるかを書く。どれがいくつ外したかは、出力の「何を：」の行に出る。

| オプション | 認めるもの |
|---|---|
| `--min-price 円` | この額以上のもの（付属品よけ。型番で探すと、安い順の上にイヤーパッドやケースが並ぶ） |
| `--max-price 円` | この額以下のもの |
| `--has 語` | 商品名にこの語を含むもの（大文字小文字・全角半角・空白・ハイフンの違いは無視） |
| `--not 語` | 商品名にこの語を含まないもの |
| `--judge 質問` | 判定モデル jev が「はい」と答えたもの |
| `--judge-cmd コマンド` | 外のコマンドが認めると答えたもの |

```bash
meguri search "WH-1000XM5" --has XM5 --not ケース --min-price 12000 --max-price 60000
```

- 条件（価格・商品名）は一覧の値にかけ、個別ページを読んだあとの値にもう一度かける（一覧と個別ページで価格が違うことがある）。判定は一覧の値に1回だけかける。
- 販路の検索は緩いことがある。ハードオフは WH-1000XM5 の検索に XM4 を返す。`--has XM5` のように、型番の一部で選ぶと外せる。
- 検索語は複数書ける（`meguri search "WH-1000XM5" "4548736132566"`）。価格.com は、JAN で探すと製品ページが出ない（0件になる）ので、型番か商品名も入れる。

### 判定を jev に任せる

「これは探している物か、付属品か」のような判断は、meguri 自身はしない。判定モデル [jev](https://openrouter.ai/docs/guides/community/jev)（TypeSafe の、文章を作らずに確率だけを返すモデル）に、はい／いいえの質問として渡せる。

```bash
export OPENROUTER_API_KEY=…
meguri search "WH-1000XM5" --judge "これは WH-1000XM5 のヘッドホン本体か（ケース・イヤーパッド・ケーブルなどの付属品や、別の型番ではないか）"
```

- 環境変数 `OPENROUTER_API_KEY` が要る。無ければ、何も取りに行かずに、使い方の誤り（終了コード 2）でやめる。キーはログに入れない。
- 売り物1件につき1回、OpenRouter の Decisions API（`POST /api/alpha/decisions`）に聞く。渡すのはその売り物の一覧の値（販路・新品か中古か・検索語・商品名・価格・送料・在庫・販売者・状態・URL）と、質問。配送先は渡さない。
- 「はい」の確率が 0.5 以上なら認める。
- 聞くのは条件を通ったものだけ。`--min-price` などを一緒に書くと、聞く数が減る。同時に聞くのは8本まで。答えはキャッシュしないので、走らせるたびに聞く。
- モデルは `typesafe/jev-1.14`。環境変数 `MEGURI_JEV_MODEL` で変えられる（確率の意味はモデルごとに違う）。
- 1件でも聞けなかったら（通信の失敗、残高不足、jev が答えを断った）、meguri はそこでやめる（終了コード 3）。聞けなかったものを認めたことにも外したことにもしない。

2026-11-21 に、楽天とハードオフの一覧120件で試した。上の質問で70件が外れ、50件（本体）が残った。

### 判定を外のコマンドに任せる

- 売り物が1行に1つの JSON で、コマンドの標準入力に渡る。

  ```json
  {"id":12,"site":"rakuten","market":"new","term":"WH-1000XM5","name":"SONY WH-1000XM5 ケース …","price":1575,"payable":1575,"shipping":"送料無料","stock":null,"seller":"…","condition":null,"url":"https://…"}
  ```

- コマンドは認めるものを1行に1つ標準出力に書く。`id` だけ（`12`）でも、`id` を持つ JSON（入力の行そのままでもよい）でもよい。`"keep": false` を付けた行と、出てこなかった `id` は外れる。
- 終了コードが 0 でなければ、meguri はそこでやめる（判定をかけなかったことにして先へ進まない）。コマンドは5分で打ち切る。

「認める行をそのまま出す」コマンドなら、そのまま判定になる。たとえば jq なら次のとおり。

```bash
meguri search "WH-1000XM5" --min-price 5000 --judge-cmd "jq -c 'select((.name // \"\") | test(\"ケース|カバー|イヤーパッド|互換\") | not)'"
```

## どこを：当たる販路の選び方

当たる販路を、探しに行く前に選ぶ。どれがいくつ外したかは、出力の「どこを：」の行に出る。

| オプション | 当たる販路 |
|---|---|
| `--only id,...` | この id の販路（id は `meguri sites` で分かる。カタログに無い id は、使い方の誤りになる） |
| `--skip id,...` | この id の販路以外 |
| `--category 語,...` | 区分の名前に、どれかの語を含む販路（例：`リユース,フリマ`） |
| `--judge-channel 質問` | 判定モデル jev が「はい」と答えた販路 |
| `--judge-channel-cmd コマンド` | 外のコマンドが当たると答えた販路 |
| `--market new\|used\|all` | 新品・中古・両方（既定は all） |

```bash
meguri search "WH-1000XM5" --category リユース,フリマ --skip jmty --min-price 12000 --has XM5
meguri search "WH-1000XM5" --judge-channel "この店は、ヘッドホンを扱っていそうか"
```

- 1つの `--only` に並べた id は「どれか」。`--only` を2つ書くと「両方に入っているもの」になる。
- 外した販路は当たらないし、「どこまで探したか」にも出ない。外した数は「どこを：」の行に出る。
- 判定には、販路が1行に1つの JSON で渡る。何を探しているかが分かるように、検索語も入る。答え方は「何を」の判定と同じ。

  ```json
  {"id":"mapcamera","name":"マップカメラ","category":"品目別の専門店","sells":["新品","中古"],"reach":"通常のブラウザ要","terms":["WH-1000XM5"]}
  ```

## どこまで：読む数と時間

- `--read N`：販路と新品・中古の組ごとに、安い順で N 件の個別ページを読む（既定は 3）。`--read 0` なら、一覧の値だけを出す。
- `--time 秒`：全体にかける時間の上限（既定は 60）。過ぎたら、読めた分だけで返し、読めなかったものを「時間切れ」として出す。足りなければ `--time` を延ばす。
  - 同じホストへは1本ずつ、2秒おきにしか取りに行かない。応答の遅い販路（楽天の個別ページは1件10秒ほどかかることがある）は、時間内に読み切れないことがある。

## 名指しのページを足す

検索がJSで描画されるサイトや、ブラウザでしか開けないサイトの商品は、見つけたページを名指しで渡すと、同じ結果の中に入る。名指しのページは「どこを」の一部で、「何を」の選び方では外れない。

```bash
meguri search "WH-1000XM5" --min-price 12000 --url "https://lohaco.yahoo.co.jp/store/h-lohaco/item/uu42216/" --page "https://www.yodobashi.com/product/100000001007090035/=saved.html"
```

- `--url URL`：HTTP で読める個別ページ（コストコ、IKEA、ソフマップ、Francfranc、LOHACO、au PAY マーケット、ロコンドなど）。
- `--page URL=FILE`：ブラウザで保存したHTML。読めるのはヨドバシ、ヤマダ、ケーズデンキ、ニトリ、Amazon、メルカリ、2nd STREET、じゃんぱら、eBay。ほかのサイトのページは、読める項目だけ読んで「一部」にとどめる。

HTMLを保存するには、ブラウザでそのページを開き、開発者ツールのコンソールで次を実行する（いま表示されているHTMLがクリップボードに入る）。

```js
copy(document.documentElement.outerHTML)
```

macOS なら、クリップボードの中身をファイルに落とす。

```bash
pbpaste > saved.html
```

ログインした状態で保存すると、名前や住所がHTMLに入ることがある。そのHTMLは人に渡さない。

## 出力の形

| `--format` | 中身 |
|---|---|
| `table`（既定） | 上の例の形。タブ区切りで、1件1行。30KB 以内に収める |
| `jsonl` | 1行に1つの JSON。確かめた候補（`meguri.result/1`）、読めなかった候補（`meguri.unread/1`）、集計（`meguri.summary/1`）、どこまで探したか（`meguri.coverage/1`）の順 |
| `md` | 報告用の表。「候補」（確認済み。画像・支払額・在庫と確認時刻・購入のリンク）、「未確認の候補」、「どこまで探したか」 |

`jsonl` の確かめた候補の1行は次のとおり。

```json
{"at":"2026-11-21T16:57:51+09:00","buy":{"contents":"カートに入れる","tag":"BuyActive"},"condition":"B RANK","confirmation":{"tag":"Confirmed"},"duplicates":[],"frame":"Secondhand","fromPage":true,"image":"https://…","keys":{"jan":null,"model":"WH-1000XM5","sharedStockId":null,"siteItemId":"2012940000135468"},"name":"SONY ノイズキャンセリングヘッドフォン WH-1000XM5","notes":["送料：都道府県ごと。MEGURI_PREF を設定すると、配送先までの送料を入れる"],"payable":null,"points":null,"priceExcl":15000,"priceIncl":16500,"schema":"meguri.result/1","seller":"ハードオフ伊勢原店","shipping":{"tag":"ByDestination"},"site":"hardoff","stock":{"tag":"InStock"},"url":"https://netmall.hardoff.co.jp/product/5323159/"}
```

```bash
meguri search "WH-1000XM5" --min-price 12000 --has XM5 --format jsonl | jq -r 'select(.schema=="meguri.result/1") | [.payable // .priceIncl, .site, .seller, .at, .url] | @tsv'
```

走らせるたびに、実行の記録が `~/.cache/meguri/runs/<id>/` に残る（7日で消える。場所は出力の最後の行に出る）。項目ごとの出どころまで入った全項目は `readings.jsonl`、一覧で見かけた売り物の全部は `sightings.jsonl`、取ったページは `pages/` にある。記録は書くだけで、あとのコマンドが読むことはない。

## 配送先までの送料

```bash
MEGURI_PREF=13 meguri search "WH-1000XM5" --only hardoff --market used --min-price 12000 --has XM5
```

`MEGURI_PREF`（都道府県コード 01〜47 か都道府県名）があると、送料を計算できるサイト（いまはハードオフとトレジャーファクトリー）で、配送先までの送料を問い合わせて、支払額まで出す。配送先は実行の記録に残さない。

## そのほかのコマンド

```bash
meguri item "https://netmall.hardoff.co.jp/product/6531583/"
```

個別ページを1つ読み、項目ごとに「どこから読んだか」をつけて出す。読めなかった項目は `null` で、理由が横に出る。ブラウザで保存したHTMLは `--html saved.html` で渡す。

```bash
meguri sold "WH-1000XM5" --min-price 12000
```

ヤフオクの落札相場。件数・最安・中央値・最高と、落札された出品が出る。`search` の「何を」の選び方（`--min-price`・`--has`・`--judge` など）が使える。

```bash
meguri recall "ヘッドホン" "headphone"
```

消費者庁と米国 CPSC のリコール情報。CPSC は英語で探すので、英語の語も並べる。題に語が入っているだけのものも混ざるので、対象の型番と期間はリンク先で確かめる。

```bash
MEGURI_PREF=13 meguri ship "https://netmall.hardoff.co.jp/product/6531583/"
```

個別ページを1つ読み、配送先までの送料を入れて出す。

```bash
meguri sites
```

販路の一覧（id・名前・区分・どの方法で読めるか）。`--only` に渡す id はここで分かる。サイトごとの注記は [docs/channels.md](docs/channels.md) にある。

```bash
meguri check --only hardoff,rakuten
```

サイトごとの健康診断。検索を1回、個別ページを1件当てて、いまも読めるかを見る。

どのコマンドにも `--format table|jsonl|md` があり、`--help` でオプションが出る。終了コードは0＝成功（一部のサイトがブロックでも成功）、2＝使い方の誤り、3＝取りに行った全サイトで失敗（か、判定が失敗）。

## 値の決まり

- 数字は作らない。読めなかった値は `null` にして、理由を書く。税抜しか書いていなければ、税込は `null`（計算しない）。送料が配送先しだいなら、支払額は `null`。
- 値ごとに出どころを持つ。一覧から読んだのか、個別ページのどこ（JSON-LD・本文など）から読んだのかが、`item` の出力と `readings.jsonl` に入る。
- 確認済みは個別ページを読んだものだけ。一覧の値から「確認済み」は作らない。
- ポイントは参考。ログインしていない状態の表示なので、実際とは違うことがある。

## サイトへの当たり方

- `meguri/<版> (+リポジトリのURL)` と名乗る。ブラウザのふりはしない。
- 同じホストへは同時に1本、間隔は2秒以上。meguri をいくつか同時に走らせても、あわせてこの決まりを守る（`~/.cache/meguri/locks/` のロックファイルで順番を待つ）。取りに行く数は、1つの meguri につき同時に8本まで。
- 取ったページはキャッシュしない。同じ検索をもう一度走らせると、サイトにもう一度当たる。
- 403・429・ボット確認が出たら、そのサイトはそこでやめて「ブロック」と記録する。解いたり避けたりしない。
- 検索結果は1ページ目だけを読む。
- 価格.com の転送URL（アフィリエイトの中継を通るもの）は、自動では開かない。
